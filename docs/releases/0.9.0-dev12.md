# CommLink 0.9.0-dev12 · 固定底部布局与通话联系人入口

拨号页线路选择与设置控件分别在常规、中等和小屏下移 18/12/8px，不挤占原键盘布局。页面外层固定，仅内容区滚动；底部导航和搜索相对稳定的应用外层定位。电话使用既有信息页的 viewport 几何处理，按可编辑焦点识别键盘、补偿视口平移，搜索与联系人编辑仍保留键盘避让。联系人海报页和新增编辑页使用一致的外层高度。

参照用户提供的 iOS 电话录屏，在通话详情加入「新建联系人」与「添加到现有联系人」。新建时带入号码；添加到现有联系人可搜索、分页选取并预览新号码。只有点击完成才保存；取消不写数据。号码已存在或达到 32 个上限时禁止追加。保存仅作用于助手统一名片，targets 为空，不修改系统通讯录。仅对有 contacts.read + contacts.write 权限的电话安装显示入口。

沿用 contacts/create、contacts/edit 的幂等请求和版本校验：未确认结果的相同提交复用 UUID；旧版本报冲突，返回列表重新读取后才能以新版本保存。号码追加不提交姓名和收藏字段。编辑期间背景禁止交互，关闭后恢复原页面和焦点。

验证：59 项 TypeScript、类型检查和发布构建通过；模拟浏览器覆盖滑动/下拉时底部稳定、搜索键盘避让、控件下移、小屏和安全区、新建/追加/取消、丢失回复重试、版本冲突、重复号码与权限限制。原 Groundwire、角标、滑动返回、短信预填、短信模拟发送与 vCard 导入/姓名修复回归通过。均未用自动测试发起真实短信或电话。

已签名覆盖安装至红米，versionCode 35；双 HTTPS 页面与资源匹配构建，未授权 API 返回 401。无数据库迁移。用户已在 iPhone 确认「位置正常，底部稳定，新增入口可见」；本次未要求用户保存真实联系人，新建/追加实际写入仍由用户按需使用。

## English

Move line selection and Settings down by 18/12/8px on regular/medium/compact displays without shifting the keypad. Lock the outer document and scroll content independently; anchor the dock/search to the app shell. Reuse the established viewport geometry for keyboard avoidance and viewport-pan compensation.

Call details now offer Create New Contact and Add to Existing Contact. Prefill the caller number, search/page through existing cards, and save only after explicit confirmation. Cancel does not write. Duplicate numbers and the 32-number limit block appending. Only assistant cards are changed; targets remain empty and system address books are untouched. Both contact capabilities are required.

Existing idempotency and revision checks protect saves. Appending changes only numbers, preserving names and favorites. Background interaction is disabled while the editor is open, and focus is restored on exit.

59 TypeScript tests, type checking, release build and mocked browser regressions pass. Tests cover layout, keyboard, contact operations, retries, conflicts, duplicates, capabilities, SMS and prior import flows without real calls/SMS. Signed versionCode 35 is installed, both HTTPS origins match the build, and no schema migration is needed. The user confirmed correct control position, a stable dock and visible contact actions on their iPhone. Real contact writes were not requested as part of acceptance.
