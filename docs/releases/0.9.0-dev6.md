# CommLink 0.9.0-dev6 · Groundwire 原生通话

网页选设备/SIM、输入号码并点击拨号后，直接使用 Groundwire 官方 Call URI 打开原生客户端并请求语音呼出。通过明确的 PBX 前缀选择实际网关和 SIM，不依赖 1001/1002 哪个账号是当前默认出站账号；Groundwire 当前出站账号仍须属于配置了这些路由的目标 PBX。

删除 SIP.js 依赖、网页麦克风采集与音频测试、WebRTC 会话、网页通话屏幕、自动/手动接续、恢复按钮、Android ARI 控制器和 SIP WebSocket 代理。旧网页拨号接口返回 410。电话页面禁止麦克风/摄像头，电话 Worker 缓存升级到 v2 并清理旧电话资源，短信 Worker 和短信资源不变。

保留联系人、备注、收藏、SIM 排序、电话配对、授权、通话记录共享和未接提醒。旧网页通话数据库作为只读历史档案保留。新拨号不制造“已接通”或通话时长，实际安卓 SIM 通话结束生成的记录通过既有目录同步进入网页。纯 SIP 内线和到达安卓前失败的呼叫不保证有安卓记录。

主节点已原签名覆盖安装 versionCode 29，并导入两张当前 SIM 的稳定线路/订阅映射。Asterisk 增加 *81*、*82* 的原生选卡路由，保留原 1001/1002、2001 及蜂窝入站规则。撤下 cl-web、cl-ws、旧 Stasis 路由与 ARI 账号，HTTP/ARI 关闭，网页新增模块列表恢复为部署前基线。私有配置备份保留在设备 Root 目录。配置文件须让 Asterisk 运行组可读；部署时修正了过严的读取权限，并确认服务恢复。

验证：40 项 TypeScript、145 项 JVM、9 项短信提交日志、3 项目录 SQL 测试通过；真机隔离 HTTPS/授权测试通过，验证原网页接口退役、/ws 移除和新路由权限；浏览器验证 Groundwire 明确 SIM 链接、无麦克风/WebSocket、联系人与通话页面及小屏/深浅色。锁文件离线冻结检查与签名 release 构建通过。部署后双 HTTPS 的 HTML/资源与本地完全一致、未授权 API 拒绝访问；原生账号和网关已注册、两条前缀加载、ARI 模块为零且 HTTP 关闭。

自动验证没有拨打真实外线。用户已实测确认：iPhone 网页直接唤起 Groundwire、实际呼出且双方有声音。用户随后确认后台及锁屏通话正常。通话记录初次未显示，排查确认系统已保存且 READ_CALL_LOG 已授予，但应用的通话记录共享开关关闭；已从安卓授权页面开启此项，后台确认历史记录与两条测试记录均已同步，待同步队列为零。

## English

The Phone PWA now opens Groundwire using the official voice-call URI from the initial dial action. Explicit authenticated PBX prefixes select the gateway and SIM independently of the selected 1001/1002 account. The active Groundwire account must still belong to the PBX containing these routes.

Removed SIP.js, browser microphone capture, audio diagnostics, WebRTC calls, browser in-call controls, handoff/recovery, the Android ARI controller and SIP WebSocket proxy. Retired call APIs return 410. Phone responses disable microphone/camera; the Phone Worker moves to cache v2. Messages resources, pairing and data remain unchanged.

Contacts, aliases, favorites, line ordering, phone authorization, Android call-log synchronization and missed alerts are retained. Earlier browser call records remain a read-only archive. Native launch is never reported as successful connection. Only calls recorded by Android are guaranteed to enter the existing synchronization path.

Installed signed versionCode 29 on the host and bound both current SIM subscriptions. Added native prefixes *81* / *82*, preserving existing native endpoints and incoming routes. Retired the web endpoint, WS transport, Stasis routes and ARI credentials; disabled HTTP/ARI and restored the pre-web module baseline. Private device backups remain private. Corrected configuration read permissions and confirmed PBX recovery.

Validation includes 40 TypeScript, 145 JVM, 9 SMS journal and 3 directory SQL tests; isolated Android HTTPS/authorization checks; browser native-link and Phone UI regression; offline frozen-lockfile verification; and the signed release build. Live HTTPS assets match the build, native accounts/gateway are registered, both prefixes are loaded, no ARI modules remain and HTTP is disabled. No automated external calls were placed. The user confirmed actual iPhone launch into Groundwire, successful carrier origination and two-way audio. The user also confirmed background and lock-screen calls remain normal. Initial missing history was traced to the disabled application-level call-log sharing switch, while Android records and READ_CALL_LOG permission were already present. Sharing was enabled through the local authorization UI. The backend confirmed both test calls and historical call records were synchronized, with no pending call deltas.
