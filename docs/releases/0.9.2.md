# CommLink 通讯互联 0.9.2

## 中文

版本号 0.9.2，versionCode 54。此版本针对主机长时间息屏提供 HTTPS 和共享手机断网后的恢复。

- 在 Android 13 及以下，启用主机或共享服务时，应用在已有 CPU 唤醒锁之外申请 Wi-Fi 高性能锁，服务停止时释放。该锁通常会增加连接 Wi-Fi 时的功耗，实际效果取决于设备。Android 14 起系统将高性能锁映射为受亮屏限制的低延迟模式，CommLink 在这些系统上保留 CPU 唤醒和网络重试。[Android Wi-Fi 锁说明](https://developer.android.com/reference/android/net/wifi/WifiManager#WIFI_MODE_FULL_HIGH_PERF)
- 在 Android 7 及以上，共享手机获得新的默认网络，或系统报告当前网络重新出现 IPv6 默认路由时，会清理空闲 HTTP 连接，提前唤醒正在退避的同步任务。连续网络事件合并处理，失败重试之间至少间隔一秒。长时间离线时继续按原有最长 32 秒间隔重试，不会因为公网异常重启主机、网关或正在处理电话的服务。
- 共享任务遇到本地初始化异常会退避重试。既有周期检查可区分同步循环停滞和持续失败超过两分钟；超时是在下一次检查时报告。停止共享将取消任务、当前 HTTP 请求和网络监听。

沿用 0.9.1 的应用包名、签名和数据库结构，可覆盖升级并保留原有配对。覆盖时 Android 会替换应用进程，主机网页或共享线路可能短暂重新连接。对 iPhone 的短信和电话界面均无需重新配对。路由器、移动网络和 APNs 的端到端可达性需要独立实测。本版构建阶段的验证覆盖本地测试和 APK，不包含自然息屏过夜或真实短信投递。

## English

Version 0.9.2, versionCode 54, addresses host Wi-Fi availability during screen-off operation and peer recovery after a network interruption.

- Android 13 and earlier devices request a high-performance Wi-Fi lock while either role is running, alongside the existing partial CPU lock. Service shutdown releases both. The Wi-Fi lock may consume more power and depends on device support. Android 14 and later map high-performance locks to low-latency mode with screen-on restrictions, so CommLink retains CPU ownership and network retries on those systems. [Android Wi-Fi lock reference](https://developer.android.com/reference/android/net/wifi/WifiManager#WIFI_MODE_FULL_HIGH_PERF)
- On Android 7 and later, a new default network or the return of its IPv6 default route evicts idle HTTP connections and wakes a peer that is waiting after a failed sync. Network events coalesce and failed attempts still have at least a one-second interval. An extended outage retains bounded retry delays of up to 32 seconds. Network events have no gateway, PBX or call-restart action.
- A peer initialization error backs off in the existing worker. Scheduled health checks report a stuck loop separately from persistent sync errors lasting over two minutes. Stopping sharing cancels the task, pending HTTP requests and network callback.

This release retains the application ID, signing identity and database schema of 0.9.1 for in-place upgrades with existing pairings. Android replaces the running application process during installation, so host pages and sharing lines may reconnect briefly. Router, cellular and APNs reachability require separate end-to-end checks. Build-stage validation covers local tests and the APK. Overnight screen-off and real SMS delivery were not exercised during the build.
