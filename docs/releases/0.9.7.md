# 0.9.7 · 从设备共享守护 / Peer sharing guard

## 中文

从设备启用共享时，Root 守护现按共享模式工作，不再把“没有开启主节点 HTTPS 服务”视为手动停止。共享偏好改变时立即更新守护状态；关闭共享或自动检测后仍不自动拉起。

在共享模式下，守护检查应用进程，并按已设置的完整检测间隔唤醒同步服务；同步服务负责实际连接检查和既有网络重试。此状态不宣称网络或运营商始终可达。恢复限额保持每小时最多三次，普通收发仍不依赖 Root。

验证：149 项发布单元测试通过，发布 APK 构建及签名校验通过。KernelSU 真机测试中，强行停止应用后约 10 秒恢复进程和主设备心跳；停止单个同步服务后，触发一次守护检查可重新启动该服务。具体恢复时间受设备系统与检测间隔影响。

配套语音网关 0.3.5-custom.6 为独立 APK，增加 IPv6 SIP/RTP、域名解析刷新和切网注册恢复。PBX 仍需正确配置公网监听与媒体地址。已实测从设备使用移动数据，经 AAAA 域名接入并通过 Groundwire 呼出，双向语音正常。仅有 AAAA 的服务无法供不具备 IPv6 的网络直接接入。

## English

The optional root guard now recognizes enabled peer sharing independently of the host HTTPS setting. Changes to sharing preferences update the guard state. Manual stop and disabled monitoring remain respected.

In peer mode it checks the process and wakes the sharing service at the configured interval. The service handles authenticated synchronization and existing network retries. This does not imply continuous network reachability. Existing recovery limits remain unchanged, and normal messaging does not require root.

Validation: 149 release unit tests passed; release build and signing verification passed. On a KernelSU device, process recovery and master heartbeat resumed about 10 seconds after force-stop. A forced guard check also restored a stopped sharing service. Timing is device-dependent.

The separate Voice SIP Gateway 0.3.5-custom.6 adds IPv6 signaling/media, registrar DNS refresh and network-change registration recovery. Correct public PBX signaling/media configuration remains required. A mobile-data peer successfully registered through an AAAA domain and completed an outgoing Groundwire call with two-way audio. AAAA-only deployments require working IPv6 on the client network.
