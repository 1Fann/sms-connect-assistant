## 中文

短信互联助手 0.8.3 加固短信提交、双手机交接和共享短信提醒。

- 短信提交手机接口前先保存持久标记，重启或替换工作任务不会自动重发结果不明的同一提交。缺少真实回执时显示“状态未知，请先核实”。结果未知不等于发送失败，也不承诺所有崩溃中的请求都能送出。
- 两部手机都升级后，使用带持久接收确认的共享协议。网络响应丢失会重新交接同一任务标识，接收端去重；新版本创建的入队中断可恢复。旧版本已遗留的未知请求保持保守处理，不盲目重发。
- 共享手机的新收件通过服务器的 Web Push 通道提醒 iPhone，尊重静音设置。首次历史导入和升级前旧短信不补发通知；推送需要已授权订阅、网络和 Apple 推送服务支持。
- 暂时断网、Apple 服务限流或服务端错误会持久退避重试，不再在三次重试后丢弃任务；订阅失效和永久拒绝会明确提示重新订阅。
- 共享任务显示“已发送”后继续查询送达或失败回执，轮换检查任务，避免旧任务被新任务挤出。共享模式补充周期恢复和心跳超时提醒，仍受 Android 后台启动和周期任务限制。

两部手机建议一起覆盖升级，原签名保留配对与数据。0.8.1 / 0.8.2 共享端仍可连接新服务器，但沿用旧交接策略，不能获得新客户端的提交防重复和确认协议。数据库升级后不支持覆盖降级旧 APK。

验证包括生产提交门控的并发与故障注入测试、生产 SQL 的持久化／迁移／丢响应／去重／轮转测试、Android 单元测试和前端测试。双手机真实短信收发仍待验证，不能将本地模拟视为运营商送达保证。

实机后续验证：两机已覆盖安装同签名 0.8.3，文件哈希及所需权限核对通过，API 确认四条 SIM 线路在线、两机历史短信合计 166 条可读取。红米插电黑屏时，分别 KILL RootMonitor 和短信业务进程，各做一次独立测试，恢复分别为 0.83 秒和 2.38 秒；后者以本机 HTTPS 与前台服务同时就绪为准，随后稳定观察 3 秒。数值包含观测开销，是单次样本；本轮未发送真实短信或推送，不证明实际送达。

红米服务器手机另完成一次无人干预重启，`deviceSecure=false`，观察者未输入解锁、启动 Activity 或发送启动服务命令。从重启请求计时，系统完成启动 37.53 秒、用户空间自动解锁 37.84 秒、短信 HTTPS 就绪 56.05 秒、全套服务就绪 62.06 秒，66.08 秒完成稳定确认。时间包含系统启动与查询开销，仅验证本机接口及服务状态。小米共享手机没有重启，不能据此宣称两机重启或实际短信送达已验证。

## English

SMS Connect Assistant 0.8.3 hardens modem submission, paired-phone handoff and shared-message alerts.

- A durable claim is recorded before calling the modem. Restarts and replacement workers do not automatically repeat an ambiguous submission. Missing real callbacks are shown as unknown; an unknown outcome is not a confirmed failure, and a crash may still leave a request unsent.
- With both phones upgraded, a versioned protocol uses durable receive acknowledgements and repeated handoff of the same request ID. The receiving queue deduplicates new requests and repairs interrupted enqueue operations. Ambiguous legacy requests remain non-retryable automatically.
- New incoming messages from the sharing phone use the server's Web Push subscriptions and respect mute settings. Initial history imports and pre-upgrade messages do not generate a notification backlog. Delivery still depends on authorization, connectivity and Apple's push service.
- Temporary network failures, throttling and server errors remain durably queued with backoff instead of being discarded after three retries. Expired subscriptions and permanent refusals explicitly request re-subscription.
- Sent jobs continue to be inspected for later delivery or failure callbacks, with fair rotation. Sharing mode gains periodic service recovery and stale-heartbeat alerts, subject to Android scheduling and background-start restrictions.

Upgrade both phones using the same signed APK to retain pairing and data. Older 0.8.1 / 0.8.2 clients can still connect but retain the legacy handoff behavior and do not gain the new submission and acknowledgement protections. In-place downgrade after database migration is unsupported.

Validation covers production submission-gate concurrency/fault tests, production SQL persistence/migration/lost-response/deduplication/rotation fixtures, Android unit tests and frontend tests. Real two-phone SMS transmission remains unverified. Host simulations do not establish carrier delivery.

Device follow-up: both phones were updated to the same-signature 0.8.3 APK, with matching file hashes and required permissions verified. API checks confirmed four online SIM lines and 166 readable history records. Two separate single-sample tests on the plugged-in, screen-off Redmi measured 0.83 seconds after killing RootMonitor and 2.38 seconds after killing the SMS business process. The latter required both local HTTPS and foreground-service readiness, followed by three seconds of stable observation. Timings include observation overhead. No real SMS or push was sent, so these checks do not establish delivery.

The Redmi server phone also completed one unattended reboot with `deviceSecure=false`, without observer-issued unlock, Activity-launch or service-start commands. From the reboot request, system boot completed at 37.53 seconds, the user was automatically unlocked at 37.84 seconds, SMS HTTPS was ready at 56.05 seconds, all services were ready at 62.06 seconds, and stability was confirmed at 66.08 seconds. Timings include operating-system startup and query overhead and cover local interfaces and service state only. The Xiaomi sharing phone was not rebooted; this does not establish two-phone reboot recovery or real SMS delivery.
